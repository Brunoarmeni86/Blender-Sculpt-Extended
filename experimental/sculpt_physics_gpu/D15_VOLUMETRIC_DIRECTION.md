# D15 — volumetric-only development line

The D14 surface experiment is retained in experiment/physics-d13-dedicated-sculpt-engines at f6f0ba6b2abb14e14cb18ab20f778efc406e4b36. D15 is a new branch, not a history rewrite. Remove recent D13/D14 dedicated surface prototypes and their standalone tests; restore the native Clay/ClayStrips/sculpt adapters to the pre-combined checkpoint (legacy V15 code remains for compatibility and is excluded in D15 configuration). Keep shared geometry guards, physical core, Warp kernels, MPM/PBF CPU and GPU prototypes and Blender DNA/RNA. Preserve all stock Blender brushes and other Sculpt Extended features. D15 default CMake configuration rejects V14/V15 experimental dispatch, excludes legacy V12 Grab and physical Clay V01 adapters, and leaves shared GPU Smooth enabled in the D15 build script. Move the uniform triangle guard out of V15 into Smooth, so multiscale/Flatten can keep using it without legacy brush execution. No new native solver or Smooth math change intended.

The active asset generator now creates exactly one native Clay Strips asset, with provisional ClayBuildup-inspired settings; not a verified ZBrush clone. No D12/D13/D14 surface material assets. Existing user libraries/preferences and previous installation remain untouched. Remove old library registrations manually in Preferences and register the new assets-d15-native library; do not delete user files. Old generator flags are no longer supported on D15. The D15 build uses a fresh installation directory and the existing build directory, reconfiguring flags. For returning to D14, use old branch/build script to restore flags.

Next: validate D15 compile and native Smooth/Clay asset, then GPU MLS-MPM/APIC, sparse grid, actual volumetric contact, local surface reconstruction, safe topology/Undo integration. Initial GPU MPM/PBF fixtures passed on user's RTX 3080; parity and native integration remain unvalidated. No test/build execution performed for this cleanup. Shared V29/legacy code, RNA and Warp artistic kernel interfaces are deliberately retained when necessary for compatibility/reuse, not offered as active surface brushes. No physical topology-changing brush is enabled yet.
