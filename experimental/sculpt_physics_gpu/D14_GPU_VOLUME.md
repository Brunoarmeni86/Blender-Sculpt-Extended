# D14 GPU volumetric reference checkpoint

Two independent Warp implementations based on our V21/V23 CPU equations. PBF: HashGrid rebuilt at each position iteration; separate density/lambda, correction, common peak, position, velocity and symmetric viscosity kernels. MPM: dense bounded 3D grid, trilinear P2G, pressure plus deviatoric stress, grid contact, G2P velocity gradient, scalar volume, pressure-dependent yield and accumulated plastic strain. PIC/small strain baseline only; not APIC/MLS-MPM. Particle/grid buffers resident and reused, CPU schedules kernels and reads one status integer per substep; rejected staged steps do not swap committed buffers. MPM equal mass and rest volume, fixed grid, rejects escape; PBF rejects overlapping sphere/floor configuration, coincident points and excessive predicted step. Not production CCD. No native PTX/C++ integration, mesh seeding, extraction or UV transfer in these prototypes; do not enable as brush dispatch yet. CUDA is explicit, never silent CPU fallback.

Validation: run test_warp_volume_d14.py --device cpu and --device cuda:0 with pinned 1.19.0; fixtures test mass transfer, ballistic motion, symmetry, rejection and rollback. Numerical parity with existing C++ V21/V23 requires richer fixtures and exported reference state, including compression, contact, shear, irregular particle distribution, many substeps. No compilation or execution claimed in this commit. No full frame transactional multi-substep orchestration, adaptive GPU timestep or final Blender mesh writer yet. Prioritize APIC/objective finite-deformation law, stable sparse grid, surface reconstruction and native backend only after tests pass.

Review of preceding D13: fixed intrinsically unbounded connected-contact propagation with a geodesic cap, preserving host masks. The new contact still chooses a vertex nearest hit (not actual ray face), cannot guarantee no crossing a short fold. Clay Fusion uses one-ring graph exchange, not a resolution-independent physical radius, conserves only new axial deposition before native guard; incomplete cross-stroke material history. Global collision V29 strict uses static separating-axis certificates, not exact CCD. Smooth sync after publication and partial-write exception handling require native integration tests. Persistent plasticity is scalar and existing attribute must be present. Artistic GPU kernels accelerate only local proposals and pair exchange; geometry/Undo stay CPU. No claim that all D13 changes compile.

## Numerical review follow-up
V21 and Warp G2P now extrapolate the particle PIC velocity into zero-mass grid nodes for gradient evaluation. Constant translation should induce zero strain even on a grid-aligned free boundary. This changes the reference numerics deliberately, not APIC. Warp PBF checks the hash-coordinate range before building the grid; invalid tentative positions retain the prior valid value and set the error flag. Added float32 domain validation and explicit CPU-vs-CUDA comparisons in the smoke script. CPU-vs-CUDA Warp comparison is distinct from C++ oracle parity. Still unexecuted here.
