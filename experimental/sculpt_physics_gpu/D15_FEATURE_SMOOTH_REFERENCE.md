# D15 feature-aware Smooth — CPU reference checkpoint

Independent implementation inspired by the feature-aware smoothing research in SCULPTCORE_INTEGRATION_MEMO.md. No upstream source copied. No native brush/UI or GPU changes; D15 baseline remains the gate for integration.

API: immutable positions/normals, native writable weights [0,1], visible/readable markers and actual incident feature-edge flags. Caller must supply full incident connectivity for writable vertices plus read-only halo. Canonical edge sorting yields deterministic reductions for fixed vertex numbering; duplicate edges rejected. Interior: one-ring mean, normal component retained by .20 default. On exactly two readable incident feature edges with equal type masks and sufficiently straight local chain, slide along the chord. Pin endpoints, mixed flags, junctions, sharp bends and inaccessible feature edges. This deliberately differs from SculptCore endpoint normal motion. Max displacement .25 shortest readable incident edge times writable weight, provisional; not a collision guarantee or exact volume conservation. Chord on a curved feature is an approximation; repeated updates may drift. Distinct chain IDs, actual UV corner discontinuity detection and attribute invalidation are native adapter tasks; tags are supplied by caller, not auto-classified. No attribute write. Zero-weight and hidden vertices remain immobile. Invalid input leaves output unchanged (allocation exceptions propagate). O(V+E log E) CPU reference, not production timing.

Fixtures: crease slide, displacement cap, mask/halo, edge order and orientation, translated fixture, half weight, UV seam tag, mixed junction/pair, endpoints, hidden feature, sharp bend, interior attenuation, disconnected nearby sample, tangent projection, hidden active, degenerate normal, transactional malformed/duplicate/NaN rejection. These are small synthetic fixtures, not dense mesh, native clipping, Undo, actual UV/Face Set classification, or Blender/Warp parity tests. CMake target registered but full CMake suite and Windows Blender build not executed here.

## Native CPU pilot (D15-B1)

Implemented in mesh/brushes/smooth.cc behind BLENDER_SCULPT_D15_FEATURE_SMOOTH=1. Explicit startup flag takes priority over existing GPU mode; no UI registration, no effect if absent. Native factors (mask, automask, texture, pressure/strength), PBVH active vertices deduplicated and one-ring read-only halo; existing vert-to-edge cache, current sharp_edge and uv_seam attributes, Face Set difference and open edges. Incident hidden faces and non-manifold/loose edges conservatively block active endpoints. This does not yet detect unmarked UV chart splits, automatic dihedral creases, or guide attributes; UV transfer is not performed. Interior Preserve Shape uses native attenuation, feature slides keep their stricter chain direction. Native clipping that alters a feature move pins that move; if the triangle guard wants to scale a clipped interior proposal, reject before publishing. Triangle guard is local, not global collision prevention. Undo/bounds use native node_mask, reset shared GPU session after writes. Ordinary Mesh only, symmetry, deform modifiers, shape keys and active layers/Multires rejected. Rejections are no-write, no silent fallback. Per-dab graph/classification CPU cost unmeasured; not an optimized GPU mode. Build/artist test required before adding UI.

Test procedure after confirming D15 baseline: start Blender with BLENDER_SCULPT_D15_FEATURE_SMOOTH=1 and BLENDER_SCULPT_SMOOTH_DIAG=1, disable all symmetry, use ordinary mesh with explicit sharp edges/marked seams/Face Sets. Inspect [D15 Feature Smooth CPU] log, compare same brush with flag removed. Verify endpoints, crease drift, open border, mask, hidden face, nonmanifold input, Undo/Redo and native clipping; do not assume mask protection beyond native factors until runtime verification. No Windows native compilation or GPU execution performed for this commit. Existing standalone oracle unchanged. No new PTX or asset required.

## D15-B2 — actual corner-domain UV boundaries

Native adapter now reads every Mesh::uv_map_names() layer via corner-domain float2 lookup. Incident edge corners are ordered by actual edge endpoint IDs, not polygon winding; a difference exceeding 1e-6 UV units in either component at either endpoint marks a chart split. UDIM offsets are not wrapped. Union across all UV maps; malformed mappings/nonfinite samples conservatively block active endpoints. Open, hidden, loose and nonmanifold cases retain B1 policies. For now actual UV splits are pinned rather than permitted to slide, because chart-aware UV reprojection and corner Undo are not implemented. Marked seams without actual splits retain the B1 chain constraint. This is classification, not UV deformation or proof of texture preservation in the interior. No UV writes, no UI, no change to default Smooth. CPU per-dab scan, no persistent UV cache; cost scales with relevant incident edges and layer count. Local topology assembly and attribute access remain unvalidated in Blender. Diagnostic [D15 UV Boundary] counts layers, split edges, invalid edges and pinned vertices (emitted after a nonempty write; all-pinned/no-motion dabs can return earlier). No new PTX.

Standalone tests actually compiled and run on Linux with GCC C++17 -Wall -Wextra -Wpedantic -Werror -O2 and Clang C++17 -Wall -Wextra -Wpedantic -Werror -fsanitize=address,undefined -O1 -g. Both printed D15_UV_BOUNDARY_REFERENCE_OK with no sanitizer diagnostic. Cases: opposite face winding, invalid corner mapping and degenerate inputs, roundoff, one-end split, UDIM, secondary map, NaN/Inf and tolerance. Native adapter test remains open: unmarked chart split, second UV layer, UV edit between strokes, open/nonmanifold and hidden topology, fully pinned region, mask, Undo/Redo, Classic mode A/B. Full CMake suite and Windows Blender compilation not executed here.

Next: chart-aware, read-only attribute transfer reference with barycentric/source-face anchors; keep geometry/UV write integration gated by native Undo and artist validation. GPU Feature Preserve remains a separate parity task.
