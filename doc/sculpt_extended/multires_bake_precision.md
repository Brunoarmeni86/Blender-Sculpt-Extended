# Bake precision: findings beyond the UV coverage candidate

This audit changes no production TBN code. It records the next precision work
after validating the partial-UV coverage candidate in native Blender.

## 1. Match the renderer transformation

The baseline/current `get_to_tangent_matrix_tbn_hq()` normalizes the interpolated
normal, projects/normalizes the tangent and constructs a normalized bitangent.
Cycles `svm_node_normal_map()` in `intern/cycles/kernel/svm/tex_coord.h` explicitly
uses unnormalized interpolated normal and tangent, then B = sign * cross(N,T),
and only normalizes the final reconstructed direction.

Consequently these are different transforms on general curved/interpolated
frames. Increasing the sample count does not make them inverse transforms.

The standalone audit extracts the actual three baker matrix helpers and supplies
portable vector/matrix services. On 216 synthetic frames, decoding through the
raw interpolated frame gives:
- legacy inverse: maximum angular difference 0.00000555 degrees;
- current orthonormal HQ inverse: maximum difference 2.734195 degrees.

These are synthetic arithmetic results, not measured errors on a Blender scene.
The frames use valid perpendicular vertex tangents but are not generated by a
native MikkTSpace mesh build. Native tests must include smooth/custom normals,
mirrored UVs, actual tangent attributes, and final renderer triangulation.

The next isolated fix should preserve HQ object-space sample averaging while
making the final Normal transform match the target shader exactly. Do not change
Vector's magnitude/space transform merely because Normal needs a direction fix:
inspect the Vector Displacement shader's basis separately.

MikkTSpace's author documents that baking must use the inverse of the shader's
transform, matching interpolation/bitangent construction and triangulation:
https://github.com/mmikk/MikkTSpace/blob/master/mikktspace.h

## 2. Use the actual target surface and normals

The bake's low surface must equal the mesh/subdivision surface receiving the map.
A base cage and the subdivided undisplaced limit surface are different references.
The fork exposes this choice through use_low_resolution_mesh.

The current base/subdivided raster builders still contain TODOs for corner normals
and use vertex normals for smooth geometry, while tangent generation has corner
normals available. Split/custom normal consistency needs an explicit audit.

For a normal/displacement pair representing the same source sculpt, inspect
Normal Map's Original Base versus Displaced Base. Original Base is intended for
matched pairs; Displaced Base is for an additional normal effect on displaced
geometry. Do not bake full sculpt normals and then accidentally interpret them
as another effect on the fully displaced surface.
https://docs.blender.org/manual/en/5.2/render/shader_nodes/displacement/normal_map.html

## 3. Preserve position, amplitude and quantization

Scalar displacement in this fork computes d = dot(N_low, P_high-P_low).
It discards the tangential part of the positional offset. Use Vector Displacement
where that part matters; higher scalar sampling cannot recover it.

Vector object space is a useful static reconstruction reference. Tangent space
needs a verified matching deformation/shader basis. Texture resolution and
receiving geometry resolution still limit reconstruction.
https://docs.blender.org/manual/en/5.2/render/shader_nodes/displacement/vector_displacement.html

For maximum numeric precision use float buffers and 32-bit FLOAT OpenEXR with
lossless compression, loading maps as Non-Color. HALF and FLOAT are distinct
formats; storage precision does not fix incorrect sampling/bases.
https://openexr.com/en/latest/concepts.html

The current scalar postprocessor writes H = 0.5 + d/(2*A), with
A = max(abs(height_min), abs(height_max)), even for float output. Correct physical
reapplication therefore needs Midlevel=0.5 and Scale=2*A, on the same object-space
reference. This function/result struct does not export A as map metadata.
A future explicit signed-distance output or exported scale metadata should avoid
guessing this factor. Rejected overlapping samples currently affect those bounds:
derive normalization from accepted resolved output instead in a separate change.

## 4. Measure round-trip error before adaptive sampling

Bake, reapply the maps to the target surface, and compare P_reconstructed to
P_high plus angle(N_reconstructed,N_high). Track RMS, worst case and seam regions.
Start in float before compression or padding; repeat after padding and final
shader sampling. This can distinguish reference-surface, TBN, coverage, filtering,
quantization and insufficient-geometry errors.

Only after that consider adaptive sampling based on local error/variation and
UV footprint, with reproducible sample positions and an explicit error tolerance.
UV island-aware filtering/padding must avoid mixing unrelated stacked islands
and must transform tangent data across mirrored/rotated seams before blending.
Neither task is implemented by the current per-triangle coverage fix.
